A review, start to finish, without a browser tab.

GitHub's web UI is built for reading one pull request. adar is built for getting through all of them. Scroll through a normal morning.

Inbox

Everything that needs you, sorted before you ask.

Review requests, your own PRs, threads you are in and what merged lately, each with its checks and review state on the row. The last inbox comes off disk before the network answers, and j k move faster than you can read because a stale fetch is cancelled, not waited for.

Files

The whole diff in one view, not forty collapsed ones.

Every file in a single native text view with syntax colour, hunk headers and both line numbers, so scrolling a big change is scrolling, not clicking Load diff. The diff and the conversation load in parallel, about a second each.

Checks

Green means green.

GitHub's rollup stays red after a flaky test passes on re-run. adar grades each check by name, so a failure followed by a success is a pass, a running shard is pending, and the name of what actually broke is right there on the row.

Agents

An agent already standing in the checkout.

⇧⌘R opens a terminal on a worktree at the PR head, with pr.diff, pr.md and pr.json beside it and ADAR_* in the environment. Claude Code, opencode, Codex, Gemini or your own command. Your working copy is never touched, and a PR title cannot escape the quotes.

Code

What changed around the change.

The repository's remote tree beside your local clone: how far behind you are, which files differ, which exist on one side only. Blame on either side, so you can see who wrote the line the PR is replacing, and when.

⌘K

Jump to anything.

Repositories, pull requests, files in the diffs you have loaded and actions on the selection, ranked as you type. @ for repos, # for PRs, / for files, > for actions. Paste a GitHub URL and it opens.

Notifications

Told when it matters, once.

Merged, approved, changes requested, checks red. Three at once become one banner, only the loud ones make a sound, and the PR you are already looking at is marked read instead of announced. Reading it in adar marks the GitHub thread read too.

Details

The small things you would otherwise script.

Built in, native, and all of it driven by the same gh login your terminal uses.

GitHub markdown

Descriptions and comments render the way GitHub renders them: task lists, tables, fenced code, alerts, collapsed details and images from private repositories.

Approve from the keyboard

⇧⌘A approves the PR you are on, and is greyed out when it is your own or already closed.

Repository view

Pick a repository in the palette to see all of its open pull requests, not only the ones that name you.

Open by URL

⌘L takes any pull-request link, from Slack or an email, and opens it in place.

Terminal drawer

Every agent and shell you start lives in a drawer on ⌘J, labelled with its PR, and says when it finishes.

A config file, watched

Agents, prompts, terminal and checkout settings live in one JSON file. Edit it in your editor and the Settings window follows.

Speed

Fast because it refuses to wait.

Every request is a gh process adar can kill. The inbox buckets are fetched side by side and drawn as each one lands; checks and reviews come in one batched query; the next PR is prefetched while you read this one.

Privacy

It runs on gh, so it sees what you see and nothing else.

No OAuth app to approve, no token to paste, no proxy in the middle.

  • Your login, not ours. adar asks gh for everything, so it has exactly the access your terminal has.
  • Straight to GitHub. Pull requests, diffs and code never pass through a server of ours. Private images are fetched with your token and only ever sent to GitHub hosts.
  • Worktrees, not your working copy. Agents get a detached checkout at the PR head. Your branch, stash and uncommitted work stay where they are.
  • Untrusted text stays quoted. A PR title or body that reaches an agent command is shell-quoted once, so it cannot run anything.

Questions

Do I need a GitHub token?

No. adar runs on the GitHub CLI and uses the login it already has. If gh auth status says you are signed in, adar works.

Can I comment on lines from the diff?

Not yet. Today you read the conversation, review threads and diff in adar, approve from the keyboard, and open the PR on GitHub (⌘O) to leave inline comments. Inline review comments are the next thing being built.

Which agents can it run?

Claude Code, opencode, Codex and Gemini CLI have profiles out of the box, and any command you can type in a shell can be added as your own, with placeholders for the PR, its diff and a prompt. Profiles whose binary is not installed are greyed out.

Does it work with GitHub Enterprise?

Not today. adar works with github.com, public and private repositories, organisations included.

Does it send anything anywhere?

Everything about your code goes between your Mac and GitHub only. The one other request is the licence check: on activation, on each launch and once a day, the app sends your key and five fields about the Mac (a hashed hardware fingerprint, its name, model, macOS version and adar version). Never a repository, a branch, a pull request or a line of code. No analytics, no telemetry.

What happens offline?

The last inbox and every diff you opened are on disk, so you can keep reading. The licence leaves the app alone for 14 days from the last successful check; only an explicit revocation, such as a refund, locks it.
